# 同欣回報（App 內主題：同欣冒險者公會）

業務用手機回報客戶進度，老闆隨時看到每個案件的進度。資料存在 Google 試算表，**沒有網路也能使用**，連上網路後會自動同步。

| 資料夾 | 內容 |
|---|---|
| `docs/` | App 本體，放到 GitHub Pages 上給大家用 |
| `apps-script/` | 放進 Google 試算表的伺服器程式 |
| `tests/` | 自動測試（開發用） |
| `prototype.html` | 早期的試看稿，只用來對照 |

---

## 一、第一次架設（約 15 分鐘）

### 步驟 1：建立 Google 試算表與伺服器程式
1. 用要管理資料的 Gmail 帳號，到 [Google 試算表](https://sheets.google.com) 建立一個新的空白試算表，命名為「同欣回報」。
2. 點上方選單 **擴充功能 → Apps Script**，會開啟程式編輯頁面。
3. 把左邊預設的 `程式碼.gs`（或 `Code.gs`）內容全部刪掉，貼上本專案 `apps-script/Code.gs` 的全部內容。
4. 點左邊「檔案」旁的 **＋ → 指令碼**，新增一個檔案，命名為 `Shared`，貼上 `apps-script/Shared.gs` 的全部內容。
5. 點左邊的齒輪 **專案設定**，勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」，回到編輯器打開 `appsscript.json`，換成本專案 `apps-script/appsscript.json` 的內容。
6. 回到 `Code.gs`，上方函式選單選 **setup**，按 **執行**。第一次會要求授權：選你的帳號 → 進階 → 前往（不安全）→ 允許。這是你自己寫的程式，可以放心。
7. 回到試算表，會看到新的工作表：**業務、案件、更新紀錄、經驗值紀錄、設定**。

### 步驟 2：設定業務名單
**可以跳過這步**：先用範例的老闆帳號（密碼 `0000`）登入 App，到「設定 → 👥 成員管理」新增業務、改名、重設密碼，並記得改掉老闆自己的密碼（設定 → 🔑 修改密碼）。

如果想直接在試算表填，在「業務」工作表一人一列：

| 欄位 | 怎麼填 |
|---|---|
| ID | **留空**，系統會自動產生，之後不要改 |
| 姓名 | 本名（App 上顯示的名字） |
| 密碼 | 4 位數字，例如 `0815` |
| 角色 | `業務` 或 `老闆` |
| 啟用 | `是`；離職的人改成 `否`（他的案件和紀錄都會保留） |
| 經驗值、角色外觀、教學完成 | 系統自動填，不用動 |

範例裡的「業務一號、業務二號」可以直接改成真實姓名和密碼。

### 步驟 3：部署成網頁應用程式
1. 在 Apps Script 頁面右上角按 **部署 → 新增部署作業**。
2. 類型選 **網頁應用程式**，「執行身分」選 **我**，「誰可以存取」選 **所有人**。
3. 按「部署」，複製出現的 **網頁應用程式網址**（`https://script.google.com/macros/s/……/exec`）。
4. 把網址貼進 `docs/config.js` 的引號裡（或直接把網址傳給 Claude 幫你填）。

> 「所有人」的意思是 App 可以連到這個網址；真正的資料仍需要正確的姓名和密碼才看得到。密碼連續錯 5 次會鎖定 10 分鐘。

### 步驟 4：放上網路（GitHub Pages，免費）
1. 在 GitHub 建立一個新的 repository，例如 `tongsin-guild`。
2. 把整個專案上傳上去（或由 Claude 協助推送）。
3. 進入 repository 的 **Settings → Pages**，Source 選 `Deploy from a branch`，Branch 選 `main`，資料夾選 **`/docs`**，按 Save。
4. 等 1～2 分鐘，網址會是 `https://你的帳號.github.io/tongsin-guild/`。把這個網址傳給業務。安裝到手機後，主畫面上的名稱是「**同欣回報**」。

### 步驟 5：業務安裝到手機主畫面
- **iPhone**：用 **Safari** 打開網址 → 下方「分享」按鈕 → **加入主畫面**。
- **Android**：用 **Chrome** 打開網址 → 右上角「⋮」→ **安裝應用程式**（或「加到主畫面」）。

第一次登入需要網路，之後沒網路也能打開使用。

## 二、日常管理（老闆）

| 想做的事 | 怎麼做 |
|---|---|
| 新增業務 | App「設定 → 👥 成員管理 → ＋ 新增成員」（或在「業務」工作表新增一列，ID 留空） |
| 改密碼 | 每個人在 App「設定 → 🔑 修改密碼」自己改；忘記密碼由老闆在成員管理重設 |
| 業務離職 | 在成員管理把他「停用」；他的案件請在 App 裡轉派給其他業務 |
| 新增服務類別 | 「設定」工作表的「服務類別」欄往下加一列 |
| 看所有資料 | 直接看「案件」「更新紀錄」工作表，或在 App 公會大廳按「📥 匯出 Excel 報表」 |
| 下載整份資料 | 試算表選單 **檔案 → 下載 → Microsoft Excel** |

**請不要修改**：各工作表的 **ID** 欄、「案件」的 **業務ID**、**系統資料** 欄，以及隱藏的「系統紀錄」工作表。其他欄位（例如客戶名稱、電話）可以直接在試算表修改。

## 三、常見問題
- **右上角的狀態是什麼？** ☁️ 已同步／⏳ N 筆待同步／📴 離線。點一下可以立即同步。
- **離線時改的資料什麼時候會到老闆那邊？** 業務的手機一連上網路就會自動送出，通常幾秒內完成。
- **有未同步的資料可以登出嗎？** 會先跳出提醒；建議連上網路同步完再登出，否則那些資料會遺失。
- **兩個人同時改同一筆會怎樣？** 每個案件只有負責的業務能改；如果業務離線時，老闆把案件轉派走了，業務那筆修改會被拒絕，App 會跳出提示。

## 四、更新 App（給維護的人）
1. 修改 `docs/` 裡的檔案後，把 `docs/sw.js` 第一行的 `VERSION`（例如 `tongsin-v1` → `tongsin-v2`）加 1，手機才會換成新版。
2. 修改了 `docs/shared.js` 的話，要把內容同樣複製到 `apps-script/Shared.gs`，並在 Apps Script 貼上新版本後 **部署 → 管理部署作業 → 編輯 → 版本選「新版本」**。網址不會變。

## 五、測試（給開發者）
```bash
node tests/server.test.js          # 伺服器：登入、權限、同步、試算表讀寫（模擬 Google 環境）
node tests/build-e2e.js            # 產生端對端測試頁
# 用 Chrome 打開 tests/e2e.html，等標題出現「DONE 通過 N 失敗 0」
```
